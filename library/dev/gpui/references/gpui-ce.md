# gpui-ce

gpui-ce is a community fork of Zed's gpui, at https://github.com/gpui-ce/gpui-ce. Its README says it is mostly API compatible with upstream and that this is changing. Treat the two as different libraries: an API, a signature or an example from Zed's gpui, docs.rs `gpui` or the zed repository is a lead, never evidence, until the same thing is found in gpui-ce's source.

Paths below are inside the gpui-ce repository, `crates/gpui/src/...` and so on. A project that vendors it has the same tree under its vendor folder; that copy is the version the project builds, so read it there.

## Telling which one a project uses

- The crate is published as `gpui-ce`. A project usually renames it back: `gpui = { package = "gpui-ce", ... }` in `[dependencies]` or `[workspace.dependencies]`, and members write `gpui.workspace = true`. A plain `gpui = "0.2"` is Zed's gpui from crates.io.
- Its siblings carry the same prefix: `gpui_ce_platform` (the platform crate an application starts from), `gpui_ce_wgpu`, `gpui_ce_windows`.
- gpui-ce has no releases and no changelog. A project pins a commit hash; the hash is the version, so write it beside any fact read from the source, never "latest".

## What gpui-ce has that Zed's gpui does not

- Its own motion stack: `motion.rs` (`Motion`, `MotionPass`, easing, iterations, alternate passes), `spring.rs` (`SpringConfig`, `SpringState`, `SpringAnimation`), `animated.rs` (`Animated<T>`), `transition.rs` (`Window::use_keyed_transition`), and style transitions (`.transitions(|t| ...)` on an interactive element, generated by `gpui_macros/src/styles.rs`). Zed's gpui has only `Animation` and `with_animation`. See the gpui-motion reference.
- A renderer split into `gpui_render` (one shader source compiled to HLSL, MSL, WGSL and GLSL by its build script) and `gpui_wgpu`.
- Quad fields such as corner smoothing and dashed borders, gradients on borders and shadows, an overflow edge fade, `Div::on_children_prepainted`, `Window::pixel_snap_bounds`.

## What it does not have

- No scale or rotate on a `div`. The only element transform is `Svg::with_transformation` (`elements/svg.rs`), applied on the GPU to a rasterised sprite. Moving a subtree without layout is `Window::with_element_offset`, callable in prepaint only, from a custom element.
- No group opacity layer. `opacity` multiplies into each primitive separately, so a faded parent with overlapping children shows the background through each child.
- No frame timestamp handed to `render`. A component reads `Instant::now()` (or the app's executor clock) when it renders.

## The renderer on each OS

Chosen at compile time by target OS in `gpui_platform/src/gpui_platform.rs`; no feature picks a backend on Windows.

- Windows: a hand-written Direct3D 11 renderer with DirectComposition and DirectWrite (`gpui_windows`). Frames are paced by a thread waiting on `DwmFlush` (`gpui_windows/src/vsync.rs`) and presented with `Present(0, 0)`. The adapter is the first one `EnumAdapters` lists that makes a Direct3D 11 device, with no high-performance preference, so a hybrid laptop may run on its integrated GPU.
- macOS: Metal through `CAMetalLayer` (`gpui_apple/src/metal_renderer.rs`), paced by `CVDisplayLink`, CoreText glyphs, grayscale text only. The `macos-wgpu` feature of `gpui_ce_platform` swaps in wgpu.
- Linux and FreeBSD: wgpu, Vulkan first then GL (`gpui_wgpu/src/wgpu_context.rs`), cosmic-text and swash for text. Wayland paces on frame callbacks; X11 on a timer at the mode's refresh rate, read once.

Shared by all three: the shaders, so shadows, paths, blur and opacity cost and look the same; device pixel snapping of quads and the four horizontal glyph subpixel variants (`text_system.rs`, `SUBPIXEL_VARIANTS_X`). A transparent or blurred window background turns subpixel text off on every OS (`Window` decides it from the window's opacity).

## Working against it

- Read the source the project builds before using an API. `grep -rn "pub fn <name>"` under the gpui crate settles most questions faster than any page.
- Prefer a fix in the project's own crates over a patch to the vendored tree. A patch needs a stated reason, a record of it beside the vendored copy, and the upstream pull request or issue that would make it unnecessary.
- Before filing upstream, search gpui-ce's issues and pull requests by symptom.
- A Windows build of `gpui_render` compiles its shaders with `D3DCompile` at build time, so it needs a Windows host.
